# Recruiting WhatsApp bot

Рекрутинговый бот на Django и SQLite. Анкетирование не зависит от транспорта:
сейчас сообщения можно вводить в терминале, а подготовленный адаптер Meta WhatsApp
Cloud API подключается настройкой окружения.

## Запуск

```powershell
Copy-Item .env.example .env
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

Панель кандидатов: `http://127.0.0.1:8000/`. Вход выполняется через собственную
страницу приложения.

Визуальный конструктор: `http://127.0.0.1:8000/questions/`. Слева — библиотека
блоков и поиск, в центре — схема с условными связями, справа — настройки
выбранного вопроса и пробное прохождение в чате. Доступны «Текст», «Число»,
«Да / Нет», дублирование и выключение вопросов. Перетаскивание меняет порядок;
для клавиатуры доступны «Выше / Ниже». Кнопки «Да +» и «Нет +» создают
уточняющий вопрос с готовым условием показа.

Изменения вступают в силу после «Сохранить сценарий» (`Ctrl+S`). Все блоки
сохраняются одной транзакцией, конфликт с изменениями из другого окна
показывается как ошибка. Доступны отмена и повтор действий (`Ctrl+Z` /
`Ctrl+Shift+Z` вне текстового поля), масштаб схемы и восстановление локального
черновика после перезагрузки. «Пройти анкету» проверяет текущий черновик
без создания кандидата; на пробный ответ можно нажать для исправления.
Сохранённые вопросы выключаются с сохранением истории, новые несохранённые
блоки можно удалить. Новых зависимостей и миграций для визуального редактора нет.

После миграции включены шесть вопросов: ФИО, возраст, учёба, судимость,
ограничения на счетах и последнее место работы. Старые стандартные вопросы
выключены, их ответы сохранены. Пользовательские вопросы остаются в списке.

Бот отправляет все доступные вопросы одним сообщением. Кандидат может ответить
свободным текстом сразу на несколько вопросов; бот сохранит распознанные ответы
и уточнит только оставшиеся. Если остался один вопрос «Да / Нет», в WhatsApp
отправляются кнопки. Кандидат также может отвечать по одному, нумеровать ответы
или писать каждый ответ с новой строки.

Для разбора свободного текста укажите `OPENAI_API_KEY` в `.env`. Модель задаётся
через `OPENAI_MODEL` (по умолчанию `gpt-5-nano`). Без ключа доступен локальный
режим: нумерованные ответы, ответы по одному или по одному ответу на строку.

Кандидат может отправить
`/ответы`, затем `/изменить 3`, чтобы исправить ответ по номеру из списка.
Сотрудник может изменить ответ в карточке кандидата кнопкой «Изменить».
После изменения сохраняются остальные подходящие ответы, ответы из веток,
условия которых больше не выполнены, удаляются. Если после правки сотрудником
появились новые вопросы, бот задаст их при следующем сообщении кандидата.

Терминальный бот запускается отдельно:

```powershell
.\.venv\Scripts\python.exe manage.py runbot --candidate 77001234567
```

Доступны команды `/typing`, `/switch` и `/quit`. Список кандидатов и открытый
диалог обновляются через WebSocket.

## Несколько номеров внутри приложения

Раздел `/numbers/` доступен сотрудникам из бокового меню «WhatsApp-номера».
Добавьте название и рабочий номер в международном формате. Номера можно
редактировать и выключать; история при выключении сохраняется. Повторное
добавление одного номера, в том числе с другим форматированием, запрещено.

«Проверить диалог» открывает локальную проверку: укажите номер тестового
кандидата и отправляйте его ответы. Сообщения и анкета сохраняются в панели,
но не отправляются в WhatsApp. Для каждого рабочего номера создаётся отдельная
карточка кандидата с независимой анкетой и перепиской. Существующие карточки
остаются в группе «Без номера». В списке кандидатов доступен фильтр по номеру.

Эта версия реализует управление номерами и проверку внутри приложения.
Регистрация в Meta, API-реквизиты и маршрутизация реальных WhatsApp-сообщений
для этих номеров пока не подключены. Имеющийся одиночный WhatsApp-транспорт
продолжает использовать настройки окружения, описанные ниже.

## WhatsApp Cloud API: настройки окружения

Заполните переменные `WHATSAPP_*` из `.env.example`, установите
`BOT_TRANSPORT=whatsapp` и зарегистрируйте публичный callback
`https://your-domain.example/webhooks/whatsapp/` в Meta. GET используется для
проверки verify token, POST проверяет подпись `X-Hub-Signature-256` через App Secret.
Для многократного тестового прохождения с одного WhatsApp-номера используйте
`BOT_TRANSPORT=whatsapp_test`: следующее сообщение после завершения очищает ответы и запускает анкету заново.

Основная логика находится в `recruiting/services.py`, а транспортные адаптеры —
в `recruiting/transports/`. Поэтому переключение транспорта не меняет анкету,
модели или панель.

## Проверка

```powershell
.\.venv\Scripts\python.exe manage.py test
```

## Production через Docker и ngrok

Заполните в `.env` `NGROK_AUTHTOKEN` токеном из личного кабинета ngrok, затем
запустите из корня проекта:

```powershell
docker compose -f docker-compose.prod.yml up --build -d
docker compose -f docker-compose.prod.yml logs -f ngrok
```

Контейнер `web` запускает миграции, собирает статику и поднимает Daphne только
во внутренней Docker-сети. Контейнер `ngrok` публикует его через HTTPS. В логах
ngrok появится публичный URL. Для стабильного адреса укажите зарезервированный
Этот адрес нужно использовать в `WHATSAPP_WEBHOOK_CALLBACK_URL` с суффиксом
`/webhooks/whatsapp/`. Для стабильного Meta webhook укажите зарезервированный
домен в `NGROK_DOMAIN`; если оставить его пустым, адрес будет случайным после
перезапуска.

Остановить сервисы:

```powershell
docker compose -f docker-compose.prod.yml down
```
